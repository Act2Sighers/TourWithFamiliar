# TourWithFamiliar プロトタイプ設計書(v0.1 ドラフト)

## 1. 目的と前提

- 目的: ゲーム構想を「すぐ遊べて、すぐ調整できる」状態にし、バランス調整とゲームデザインの検証を高速に回す。
- 第1段階: ブラウザ(HTML/JavaScript)で即プレイ可能なプロトタイプ。
- 最終段階: 調整が固まったらUnity(C#)に置き換える。**移植しやすさを設計の最優先制約とする。**
- トーン: ポップ/コミカル寄り、ファンタジー、モチーフは「甘いもの」。食べ物・料理・スイーツの言い回しを多用する。
- 世界観: 現実と法則の異なる異世界。同じ外見/性格のキャラが複数人、個々の自我を持って存在するのは普通のこと。キャラは基本的に少女の姿。

## 2. ゲームの定義

リアルタイム・ローグライト・シミュレーション。見下ろし視点、上下左右移動、シームレス進行。

| 用語 | 役割 |
|---|---|
| 観測者 / Watcher | プレイヤーの分身。**操作は移動のみ**。戦闘手段なし。管理(後述)を担う。 |
| ファミリア / Familiar | お供。**AIが自動操作**。移動・防御・攻撃・回復・探索など多様な行動をとる。 |

### 観測者の特権(管理行動)
1. 新しいファミリアを仲間に加える
2. ファミリアを離脱させる
3. 安全な場所へ送還する
4. 旅に連れ出す(帯同させる)
5. コミュニケーションを取る
6. ローグライトらしい報酬・アップグレードの分配を決める

### 世界と状態遷移
- ステージ選択やマップ画面は無い。**事実上無限に広がる2次元平面を歩き続ける。**
- アップグレード画面やメインメニューは、ワールド上にオーバーレイとして呼び出す(ワールドの時間進行の扱いは調整項目)。
- 「ローグライト」: ラン内の成長に加え、ラン間で持ち越す要素(恒久強化)を持つ。

## 3. プロトタイプの中核の問い(検証したいこと)

1. 「操作できない戦闘を見守り、管理で勝たせる」体験は面白いか。
2. ファミリアのAI行動が、プレイヤーに「育てている」実感を与えるか。
3. 観測者が無力であることの緊張感(守られる/守る)は成立するか。
4. 報酬分配や仲間の入れ替えが、意味のある選択になっているか。

## 4. システム構成

移植を前提に、**ロジック層と描画/入力層を厳密に分離**する。

```
src/
  core/        // 純粋ロジック。DOM・Canvas・ブラウザAPIに依存しない
    sim/       // World, Entity, 固定タイムステップのシミュレーション
    ai/        // ファミリアAI(行動選択)
    systems/   // Combat, Care(世話), Party(編成), Reward, Spawner
    data/      // JSONで外出しされたパラメータ・定義
    rng.js     // シード可能な乱数(再現性・Unity側との照合用)
  view/        // Canvas描画、カメラ、エフェクト
  ui/          // オーバーレイ(メニュー、アップグレード、会話)
  input/       // キーボード/ゲームパッド → 抽象化された入力
  debug/       // チューニングパネル、ログ、スロー/停止/コマ送り
```

### 移植性のルール(Unity C#へ向けて)
- ロジック層は「クラス + 明示的な状態 + update(dt)」のみで書く。クロージャや動的な型変換に頼らない。
- 固定タイムステップ(例: 60Hz)で更新。描画は補間のみ。
- 乱数は自前のシードRNG。毎フレームの副作用は避け、同じシード・同じ入力で同じ結果になるようにする。
- パラメータは全てJSON(将来ScriptableObject / JSONへ変換可能)。コードに数値を直書きしない。
- ECSほど重くせず、「Entity + コンポーネント的なプレーンデータ + System」で構成し、C#のクラス/structに素直に対応させる。
- 各モジュール先頭に、C#での対応クラス名のメモを残す(例: `// C#: FamiliarBrain`)。

### 無限ワールド
- チャンク方式(例: 固定サイズのタイル/領域)。プレイヤー周辺のみ生成し、離れたものは破棄または軽量化。
- チャンクの内容はシード+座標から決定的に生成(再訪時に同じ内容、または状態差分を保存)。
- 「安全な場所」(送還先)は、世界のどこかにある拠点的エリアとして扱う。位置と意味付けは要検討。

### ファミリアAI(初期案)
- Utility AI(行動ごとにスコアを計算し最大を選ぶ)を基本とする。
  - 行動: 追従 / 攻撃 / 防御 / 回復 / 探索 / 待機 など。
  - 入力: 体力、周囲の脅威、観測者との距離、個体の性格パラメータ、空腹度(世話の状態)。
- 個体ごとの性格・成長を数値で持つ(同じ外見でも別個体として振る舞う)。
- 行動のスコアと選択理由をデバッグ表示できるようにする(調整のため必須)。

### 世話(Care)
- 最初は「甘いもの」をモチーフにした単純な指標(例: 満腹/機嫌/疲労)から始める。
- 世話が戦闘力・AIの行動傾向に影響する関係が、ゲームの核になる。

## 5. 調整のしやすさ(最重要)

- 画面内のチューニングパネル: JSONの数値をスライダー/入力でリアルタイム変更。
- 変更内容を保存/読み込み(localStorage + エクスポート)。
- シード固定リプレイ、スロー再生、一時停止、コマ送り。
- 計測表示: 戦闘ログ、与ダメ/被ダメ、各行動の選択比率、クリアまでの時間など。
- ヘッドレス実行できるロジック層により、自動で大量シミュレーションを回してバランスを集計できるようにする(将来)。

## 6. マイルストーン案

| 段階 | 内容 | 判定基準 |
|---|---|---|
| M0 | 土台: 固定タイムステップ、観測者の移動、無限スクロール、デバッグ基盤 | 歩き続けられる |
| M1 | ファミリア1体 + 基本AI(追従/攻撃) + 敵と戦闘 | 戦闘が自動で成立する |
| M2 | 複数ファミリア、AI行動の拡張(防御/回復/探索) | 行動が可視化され調整できる |
| M3 | 管理行動(加入/離脱/送還/帯同/会話) | 観測者の管理が意味を持つ |
| M4 | 報酬・アップグレード分配、オーバーレイUI、ラン間成長 | ローグライトのループが回る |
| M5 | 世話(Care)システムと戦闘への連動、世界観の演出 | 育成の実感がある |
| M6 | バランス調整、Unity移植計画の確定 | 移植対象の仕様が固まる |

## 7. 未決事項(都度確認したい)

- 技術: 素のJavaScript(ESモジュール)にするか、TypeScriptにするか(C#移植のため型情報があるTypeScriptを推奨)。
- 描画: Canvas 2Dで十分か。アセットは当面プレースホルダー(図形)でよいか。
- 入力: キーボードのみか、ゲームパッドも想定するか。
- オーバーレイ表示中の世界の時間(停止 / 減速 / 継続)。
- 失敗条件(観測者が倒れたらどうなるか)とラン間成長の範囲。
- 「安全な場所」の位置づけと、送還されたファミリアの扱い。
- 世話に使う「甘いもの」の具体的なアイテム/指標。
